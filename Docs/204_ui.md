# 204 — UI 구현

> 화면 흐름과 각 화면 명세. 소유: UI/통합 담당 (Boot·Result 씬) + 각 씬 소유자(자기 씬의 UI 배치).
> **공용 UI 킷 방침은 `201_common.md` 4장 — 각자 자체 제작 UI 금지, 킷 프리팹만 사용.**

## 1. 화면 흐름

```
Boot (상주 — 로비·방 화면·뜻 선택·대기 오버레이·결과 화면은 Boot 의 런타임 UI)
 └ Lobby ────────────── 닉네임, 방 만들기 / 코드 참가
    └ 방 화면 ─────────── 방 코드(복사)·플레이어 2칸·방 설정 5종(방장만 조작, 참가자 실시간 반영)·[게임 시작](방장)·[방 나가기]
       └ 뜻 선택 ────────── 후보 카드 중 N개 선택·확정 (라운드마다)
       └ MapEditor ─────── 맵 제작 + 검증 플레이(같은 씬 안, 상대 뜻) → [완료] = 제출 → 대기 오버레이
          └ Play(교환) ───── 자기 뜻으로 상대 맵 플레이 → 결과 대기 오버레이
             └ Result ──────── 승/패/무 + 양쪽 기록 → [다음 라운드](뜻 선택으로) / [방 나가기]
```

- 화면 전환은 Boot FSM(`GameFlow`)이 제어 — UI는 전환 요청만 발행 (`205_network.md` 4장)
- 검증 플레이는 Play 씬으로 가지 않고 MapEditor 씬 안에서 진행된다 (`100_game_design.md` 6장)
- "양쪽 제출 완료 대기"·"상대 결과 대기"는 MapEditor / Play 씬 위의 대기 오버레이로 처리 (제출 후 수정 불가)
- 연결 끊김 시 어느 화면에서든 결과 화면 자리에 **매치 무효** 화면

## 2. 화면별 명세

### 2.1 Lobby (구현: `GameFlow` 런타임 UI)
| 요소 | 내용 |
|---|---|
| 구성 | 제목·태그라인 아래 카드 1장(방 화면 패널과 같은 색): 닉네임 → [방 만들기] → "또는 코드로 참가" → 코드 입력 + [참가] → 안내 문구. 카드 아래 상태 문구 |
| 닉네임 입력 | **필수** (최대 12자, 한글 가능). 비어 있으면 [방 만들기]·[참가] 모두 비활성 + 빨간 "필수" 표시. 기본값 없음. **WebGL** 에서는 uGUI InputField 가 한글 IME 를 못 받아 클릭 시 브라우저 prompt 로 입력 (`Scripts/Common/WebPrompt.cs`) |
| [방 만들기] | 닉네임 입력 시 활성. 방 생성 → **방 화면**(2.1b)으로 전환 (방장) |
| 방 코드 입력 + [참가] | 닉네임 + 코드(4자 이상) 입력 시 활성. 코드는 대문자로 정규화 → 방 화면 (참가자) |
| 오류 문구 | 초기화 실패·방 생성 실패·참가 실패는 상태 문구 1문장으로 표시 |

### 2.1b 방 화면 (`GameFlow` 런타임 UI — `MatchState.RoomLobby`, 2026-09-06 구현)
| 요소 | 내용 |
|---|---|
| 방 코드 | 크게 표시 + [코드 복사] (클립보드) |
| 플레이어 | 방장 / 참가자 2칸. 비어 있으면 "대기 중...", 나는 "(나)" 표시 |
| 방 설정 5종 | 시도 제한(무한/3/5) · 그리기 시간(2/5/10분) · 플레이 시간(2/3/5분) · 뜻 개수(1~3) · 뜻 후보 수(3/5/8/전체). `<` `>` 로 순환. **방장만 조작**, 바꾸는 즉시 `CJ_Settings` 로 참가자 화면에 반영. 뜻 개수는 후보 수를 넘지 않게 자동 보정 (`100_game_design.md` 7.1) |
| 안내 | 각 설정이 어디에 적용되는지 한 줄씩 |
| [게임 시작] | **방장만**. 참가자가 연결(Hello 교환)되기 전에는 "상대를 기다리는 중..."으로 비활성. 누르면 `CJ_Start`(최종 설정 포함) → 양쪽 뜻 선택으로. 참가자가 들어와도 자동 시작하지 않는다 |
| [방 나가기] | 세션 종료 후 로비 초기 상태로 복귀 |
| 상태 문구 | 연결 진행·상대 입장·복사 완료 등 1문장 |
| 새 상대 대기 | 매치 무효 뒤 방장이 [같은 방에서 새 상대 기다리기] → 같은 방 화면으로 복귀 (설정 유지, 라운드 1부터) |

### 2.1a 뜻 선택 화면 (라운드마다, Boot 런타임 UI)
| 요소 | 내용 |
|---|---|
| 제목 | "라운드 N — 뜻을 M개 고르세요" (M = 방 설정 뜻 개수) |
| 후보 카드 | 방 설정 후보 수(기본 5)만큼 가로 배열. 카드 = 뜻 이름 + 한 줄 설명 + 난이도 ★. 클릭으로 토글, M개가 차면 가장 먼저 고른 것을 교체. "뜻 없음" 카드 없음 |
| [확정] | M개 선택 시 활성화. 누르면 "확정됨"으로 바뀌고 상대에게 뜻 전송 |
| 힌트 | 확정 전: "내가 고른 뜻은 상대 맵을 플레이할 때 나에게 걸립니다" / 확정 후: "상대가 뜻을 고르는 중..." / 상대가 먼저 골랐으면 상대의 뜻 표시 |
| 진행 | 양쪽 확정 시 자동으로 MapEditor 로 전환 |
| [방 나가기] | 우하단 |

### 2.2 MapEditor (구현: `Prefabs/UI/MapEditorHud.prefab` + Boot 오버레이)
| 요소 | 내용 |
|---|---|
| 상단 | **라운드 배지**(라운드 번호), **안내문**(도구·상태별 문구), **타이머 링**(그리기 남은 시간, 10초 이하 경고색. 만료 = 제출 실패 — `100_game_design.md` 6장) |
| 오른쪽 도구 열 | 펜 / 지우개 / 실행취소 / 전체 지우기 / 골 배치 (`203_map_editor.md` 1장). 다시실행은 Ctrl+Y 단축키만 |
| 하단 | **굵기** 3단계(지우개 반지름 연동) · **색상** 팔레트(StrokePalette 항목 수만큼 생성) · **상태 칩**(스트로크 n/60 · 점 수 · 골 여부 등) · [검증하기] · [완료] |
| [검증] | 편집 가능한 동안 **항상 활성**(코랄 원형). 골이나 선이 없으면 상태 문구로 이유 안내("골을 먼저 배치하세요" / "선을 하나 이상 그리세요"). 같은 씬 안에서 검증 플레이 시작 (HUD 조작부는 숨김, Play HUD 표시 — 2.3) |
| [완료] | 검증 성공 상태에서만 활성화. 누르면 제출 확정 → 에디터 잠금 |
| 우상단 [방 나가기] | Boot 가 에디터 위에 띄우는 작은 띠. 검증 플레이 중에는 숨김 (Play HUD 와 겹침 방지) |
| 왼쪽 여백 "상대의 뜻" 패널 | Boot 가 종이 영역 왼쪽 여백에 띄움: 상대의 뜻(굵게) + "상대는 이 제약을 지키며 내 맵을 플레이합니다. 검증도 이 뜻으로 합니다" + 내 뜻. 검증 플레이 중에는 숨김 |
| 대기 오버레이 | 제출 후 "맵 제출 완료. 상대가 맵을 완성할 때까지 기다립니다..." / 상대 맵 수신 진행 "상대 맵 수신 중 n/N" |
| 안내 문구 | 시작점 고정·골 배치 필수·검증 후 완료 가능 등은 안내문/상태 문구로 표시 |

### 2.3 Play HUD (구현: `PlaySession` 런타임 HUD — 검증·교환 공용, 상단 한 줄)
| 요소 | 내용 |
|---|---|
| 모드 제목 | "검증 플레이 — 상대 뜻: …" / "교환 플레이 — {상대}의 맵" |
| 타이머 | 교환 플레이: **남은 시간**(플레이 시간 제한 − 경과). 검증 플레이: **남은 수정 시간**(라운드 그리기 시간) — 검증 자체 제한 없음 |
| 시도 | "시도 n" 또는 시도 제한 설정 시 "시도 n/N" |
| 뜻 상태 | 적용 뜻 상시 표시 + 실시간 상태 ("뜻: 저속 · 점프 5회 (점프 3회 남음)") |
| 조작 안내 | 이동 A/D·←/→, 점프 W·↑, S·↓ 빠른 낙하, R 리스폰 |
| 우측 버튼 | 교환: **[기권 (ESC)]** → 미클리어로 종료. 검증: **[에디터로 돌아가기 (ESC)]** |
| 종료 문구 | 화면 중앙 "클리어! n초 (시도 n)" / "미클리어 — 사유". 교환은 "상대 결과 대기", 검증은 클리어·시간 만료 모두 "잠시 후 에디터로 돌아갑니다" |
| 10초 이하 강조 | 미구현 |

### 2.4 Result (구현: `GameFlow` 런타임 UI — 매치 무효 화면 겸용)
| 요소 | 내용 |
|---|---|
| 판정 | **승리 / 패배 / 무승부** 크게 표시 (`206_ranking.md`). 제출 실패 라운드도 같은 화면(승/패, 양쪽 실패면 무승부) |
| 점수 | 판정 아래 3줄 — 윗줄(작게): 양쪽 식 `클리어 시간 × 뜻 계수 − 검증 {패타임}` / 가운데(크게): 양쪽 마진 `+2.13s vs −0.40s` (유리한 쪽 초록, 미클리어는 "미클리어") / 아랫줄: 전적 (`206_ranking.md` 2장) |
| 양쪽 기록 | 맵 썸네일 2장(내가 만든 맵·상대가 만든 맵, 각 패타임과 상대 기록 캡션) + "라운드 N", 각자의 뜻, 뜻 계수 줄 |
| [다음 라운드 (같은 방)] | 누르면 "상대 대기 중..."으로 바뀌고 양쪽이 누르면 다음 라운드 뜻 선택으로. 상대가 먼저 눌렀으면 힌트 문구 |
| [방 나가기] | 세션 종료 → 로비 |
| 매치 무효 (연결 끊김) | 제목 "매치 무효" + 사유. 호스트만 **[같은 방에서 새 상대 기다리기]**(같은 방 코드로 대기, 라운드 1부터) + [방 나가기]. 참가자는 [방 나가기]만 |

## 3. 공용 UI 킷 (통합 담당 제작·배포)

| 컴포넌트 | 스펙 |
|---|---|
| 버튼 프리팹 | 일반/눌림/비활성 3상태 |
| 패널 프리팹 | 9-slice |
| 토글 | 방 설정용 |
| 인풋 필드 | 방 코드/닉네임 |
| 폰트 | 한글 지원 무료 폰트 1종 (`102_required_assets.md` — 기본 폰트 한글 깨짐 주의) |
| 색 팔레트 | 테마 ScriptableObject (`201_common.md` 5장) |

- 해상도: 1920×1080 기준, Canvas Scaler = Scale With Screen Size
- 플레이스홀더 아트로 시작 — 교체는 프리팹/테마만 바꾸면 전체 적용되도록 (`201_common.md` 아트 방침)

### 구현 현황 (2026-09-06)

- **MapEditor HUD** 가 첫 번째 시안 기반 화면: `Prefabs/UI/MapEditorHud.prefab` + 테마 `UI/MapEditorTheme.asset` + 이미지 `Assets/image/` — 상세 `203_map_editor.md` 9장. 네이비 배경·아이보리 종이·초록 강조·코랄 경고 팔레트가 테마 SO 에 있으므로 Lobby/Play/Result 도 같은 색과 `Assets/image` 패널·버튼 스프라이트(9-slice 보더 설정 완료)를 쓰면 통일된다
- 폰트는 아직 `LegacyRuntime.ttf`(OS 한글 폴백). 시안의 둥근 굵은 한글 폰트는 `102_required_assets.md` 대로 무료 폰트 1종을 들여와 프리팹 텍스트에 일괄 지정해야 한다
- Lobby·뜻 선택·Play HUD·Result·대기 오버레이·에디터 위 "방 나가기"/"상대의 뜻" 패널은 여전히 `RuntimeUI` 플레이스홀더 (`GameFlow.BuildUI`, `PlaySession.BuildHud`)

## 4. 메시지/문구 기준

- 짧고 명확하게. 뜻 설명은 한 줄 (예: "저속 — 이동 속도가 절반이 됩니다")
- 상태 안내 문구: "상대의 뜻으로 클리어하세요" (검증), "자기 뜻으로 상대 맵 클리어" (교환)
- 오류 안내: 방 코드 틀림 / 연결 끊김 / 시간 만료 시 각각 1문장
