# 206 — 랭킹 & 결과 구현

> 기록 데이터 구조와 랭킹 계산. 소유: 통합 담당 (Result 씬) — 계산 로직은 공유 타입으로.
> 룰 근거: `100_game_design.md` 7장.

## 1. 기록 데이터

```csharp
class PlayerRecord {
    bool Cleared;        // 클리어 여부
    float ClearTime;     // 클리어 시간(초) — 시작부터 골 도달까지
    int AttemptsUsed;    // 사용한 시도 횟수 = 1 + R키 수동 리스폰 횟수 (낙하 자동 리스폰은 미소모)
    bool GaveUp;         // 미클리어 (시도 제한 소진 또는 플레이 시간 만료)
}
```

- 전송/비교에 쓰는 유효 시간: `EffectiveTime`(아래 2장)
- 패타임: 검증 플레이(상대 뜻으로 자기 맵 클리어)의 클리어 시간 — `MatchData.MyParTime` (`201_common.md` 3장)

## 2. 랭킹 공식 — 패타임 빼기 (2026-09-06 확정, 단일 공식)

```
score(마진) = 클리어 시간 × 뜻 계수(2.5) − 패타임(내가 플레이한 맵 제작자의 검증 기록)  →  낮을수록 승
```

- 패타임은 제작자가 **내 뜻으로** 자기 맵을 클리어한 시간(검증 플레이)이라 같은 맵·같은 제약의 기준선이다. 그래서 서로 다른 맵의 절대 시간을 비교하지 않고 "제작자보다 얼마나 빨랐/늦었나"를 비교한다 → 클리어를 질질 끌게 짠 맵을 받아도 불리하지 않다
- 음수 = 제작자보다 빨랐다. 결과 화면은 식(작게) + 마진(크게) + 전적으로 표시 (`204_ui.md` 2.4)
- 전략: 제작자는 검증을 빨리 끝낼수록(패타임 ↓) 유리하고, 그리기 시간을 검증 연습에 쓸지 맵 다듬기에 쓸지 고르게 된다. 시작점 옆에 골을 둔 날림 맵은 패타임도 작아 이득이 없다
- 성질: 긴 맵은 같은 비율 차이도 초 단위 마진이 커져 승부를 지배한다 ("긴 맵 = 판돈 큰 무대"). 의도된 전략 요소로 둔다. 비율 방식 `(시간−패타임)÷패타임`은 초 단위 직관이 사라지고 짧은 패타임에서 수치가 튀어 채택하지 않음
- 과거 안(폐기): "패타임 모드" 토글 — 끔이면 절대 시간 비교, 켬이면 `시간 ÷ 패타임`. 방 설정에서 제거됨 (5종)

### 2.3 EffectiveTime 산출

| 상황 | 값 |
|---|---|
| 클리어 | 실제 클리어 시간 |
| 미클리어 (시도 소진 또는 플레이 시간 만료) | `EffectiveTime = PlayTimeLimit` (표시용). 판정은 점수 이전에 클리어 여부로 먼저 갈린다 (아래) |
| 클리어 불가 (시도 무제한) | 플레이 시간 제한으로 반드시 종료 → 위 미클리어 처리 |

> **클리어는 미클리어를 항상 이긴다**, **둘 다 미클리어면 무승부** (구현 `Ranking.Judge` 첫 단계). 패타임을 빼는 공식에 미클리어를 그대로 넣으면 "상대가 검증을 느리게 한 쪽이 승"이라는 무의미한 판정이 나오므로 점수 비교는 둘 다 클리어했을 때만 한다.

### 2.5 뜻 계수 (초지일관 보상 — 2026-09-06 확정)

뜻은 코드가 **하드 강제**한다 (어길 수 없음 → 제작자의 맵 설계 보호). 주제 "초지일관"은 한 판 안의 굽힘이 아니라 **매치 전체에서 같은 뜻을 유지하는가**로 표현하며, 클리어 기록에만 두 계수를 곱한다.

```
최종 시간 = 클리어 시간 × 난이도 계수 × 일관성 계수     (미클리어는 계수 없음) → 여기서 패타임을 뺀 값이 점수 (2장)
난이도 계수 = Π 선택한 뜻의 Tier 계수   (Tier 1 ×1.00 / 2 ×0.97 / 3 ×0.94 — VowCatalog.TierCoefficient. 패타임이 이미 내 뜻의 난이도를 흡수하므로 이중 보상을 피해 작게 둠)
일관성 계수 = 같은 뜻 조합을 연속 유지한 라운드 수   (1 ×1.00 / 2 ×0.95 / 3 ×0.90 / 4+ ×0.85 — VowCatalog.ConsistencyCoefficient)
```

- 상대는 내가 뜻을 유지할 것을 알고 라운드가 갈수록 그 뜻을 노린 맵을 짠다 → 굽히지 않을지(계수 유지) 바꿀지(계수 리셋)의 긴장이 뜻을 건 사람 자신에게 걸린다
- 뜻을 바꾸면 연속 카운트는 1로 돌아간다. 뜻 이력은 `MatchData.MyVowHistory / OpponentVowHistory` (방을 나가거나 새 상대를 받으면 초기화)
- 구현: `VowCatalog.ScoreMultiplier`, `Ranking.Score/Judge`의 `vowMultiplier` 인자, 결과 화면 "뜻 계수" 줄과 "초지일관" 배지
- 검토했다가 폐기한 안: 소프트 뜻(위반 시 시간 페널티) — 러너가 페널티를 내고 맵을 우회할 수 있어 제작자의 설계를 무력화하므로 채택하지 않음. "라운드당 1회 굽힘 토큰"은 시간이 남을 때 재검토

### 2.4 동점 처리

1. (둘 다 클리어) 마진 동일(±0.005s) → 시도 횟수(`AttemptsUsed`) 적은 쪽 우위
2. 그래도 동일 → **무승부** 표시
3. 둘 다 미클리어 → 바로 **무승부**

## 3. 승패 구조

| 비교 | 내용 |
|---|---|
| A의 점수 | A가 B의 맵을 A의 뜻으로 클리어한 시간 × A의 뜻 계수 − B의 검증 기록(패타임) |
| B의 점수 | B가 A의 맵을 B의 뜻으로 클리어한 시간 × B의 뜻 계수 − A의 검증 기록(패타임) |
| 판정 | 클리어 > 미클리어, 둘 다 클리어면 점수(마진) 낮은 쪽 승, 둘 다 미클리어면 무승부 |

- 결과 화면 표시 데이터: 양쪽 식·마진·패타임·전적, 승자 — `204_ui.md` 2.4
