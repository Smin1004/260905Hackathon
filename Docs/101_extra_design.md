# 101 — 추가 기획

> 코어가 아닌 기획. **코어(MVP)가 안정화된 이후, 남은 시간이 있을 때만** 검토한다.
> 이 문서의 항목은 개발 일정에 기본 포함되지 않는다. 코어는 `100_game_design.md`.

## 1. 색상별 오브젝트 시스템 ⭐ 최우선 검토

드로잉 툴의 색상에 따라 오브젝트의 성격이 달라진다. 유저는 모양만 그리고, 기능은 색이 결정한다.

### MVP 3색

| 색 | 기능 | 구현 개념 | 난이도 |
|---|---|---|---|
| ⬛ 검정 | 땅/벽 (고체) | 스트로크 → `EdgeCollider2D` (코어의 기본 동작) | 기본 |
| 🟦 하늘색 | 은폐 구역 — 진입 가능, 구역 안에서는 플레이어가 보이지 않음 | 스트로크가 닫힌 영역이면 내부 판정, 진입 시 플레이어 스프라이트 알파 0 — **미구현** (현재는 벽으로 동작, `StrokeBehaviours.Attach` 의 TODO) | 중 |
| 🟨 노랑 | 닿으면 골 | 트리거 콜라이더 + 골 판정 — **미적용** (골은 코어의 골 배치 버튼으로만, 노랑 선은 벽) | 하 |

- **하늘색 은폐 구역 디테일 (채택된 방향)**: 구역 안에서는 **자기 캐릭터만 안 보이면** 충분 (스프라이트 투명화만으로 구현 단순). 주변 맵 가림(카메라 처리)은 더 나아간 옵션
- 은폐 구역의 게임적 의미: 러너가 자기 위치를 잃어 긴장감 상승, 제작자는 은폐 구역으로 코스를 숨길 수 있음

### 스트레치 색 (시간이 남으면)

| 색 | 기능 | 구현 개념 |
|---|---|---|
| 🟩 초록 | 바운스 오브젝트 — 밟으면 위로 튕김 | **구현됨** — 착지하거나 걸어서 올라선 발밑이 `BounceStroke` 면 상승 속도 = JumpSpeed × 1.3 (물리 머티리얼 바운스는 플레이어 마찰 0 재질과의 조합 규칙 때문에 미사용). 점프 카운트·쿨다운 미소모, 키 떼기 컷 없음 |
| 🟦 파랑 | 얼음 — 마찰 거의 없음 | **구현됨** — 서 있는 동안만 `SurfaceModifier` 적용: 지상 가속 0.5s·감속 0.6s **하한**, 정지 마찰 ×0.05. 뜻이 정한 기준값은 덮어쓰지 않음 → "미끄러운 발" 뜻과 겹치면 마찰만 더 낮아짐 |
| 🟥 빨강 | 위험 구역 — 닿으면 시작점 리스폰 | **구현됨** — 벽 콜라이더 유지(트리거 아님) + `HazardStroke` 접촉 시 `PlayerController.HazardTouched` → `PlaySession.Respawn(countsAsAttempt: false)` (시도 미소모, 사망 연출 0.2s) |

### 구현 현황 (2026-09-06)

- 매핑: `Scripts/MapEditor/StrokeBehaviours.cs` — `StrokeColorId` 상수(팔레트 번호 고정) + `HazardStroke` / `BounceStroke` / `SurfaceModifier` 컴포넌트. `MapLoader` 가 **`BuildColliders` 일 때만** 부착 → 에디터 미리보기에는 시각만, 검증·교환 플레이(같은 `PlaySession` 경로)에는 동일 적용
- 수치는 `MapLoader.ColorBehaviours`(인스펙터: 바운스 배율 1.3 / 얼음 가속 0.5·감속 0.6·마찰 ×0.05) — ⚠ 확인 필요: 제안값, 플레이 테스트 후 조정
- 플레이어 쪽: `PlayerController` 가 지면 BoxCast 최근접 히트의 콜라이더를 캐시해 얼음·바운스 컴포넌트를 읽는다. `OnCollisionEnter2D` 로 위험 구역만 감지 (다른 색 기능은 PlayerController 가 색을 모름)
- 검정·노랑은 기본 벽. 하늘(은폐)은 닫힌 영역 판정이 필요해 미구현 (TODO)

### 코어와의 연결

- 코어의 에디터는 "펜 + 골 배치 버튼" 2기능. 색상 시스템 도입 시 골 배치 버튼이 **노랑 색상**으로 흡수됨
- 구조상 선 준비: `StrokeData`에 색상 ID 필드를 미리 포함 (코어에선 항상 고정값) — `203_map_editor.md`

## 2. 3·4인 확장

- 방식 후보: 라운드 로빈 (각자 자기 맵을 모두에게 배포, 모두가 각자의 뜻으로 플레이) — 구조상 자연 확장
- 랭킹: 전 플레이어 기록 합산 순위
- 우선순위: 낮음. 2인이 안정화된 후 검토. UI(로비 인원 카운트)만 미리 고려

## 3. 라이브 관전

- 상대가 그리는 스트로크를 실시간 전송해 보여주는 기능 (갈틱폰의 재미 요소)
- 비용이 큼 (실시간 스트로크 동기화) → 스코프 아웃 상태. 대안: 그리기 완료 후 결과 화면에서 상대 맵 공개 (현재 코어안)

## 4. 기타 아이디어 (보관함)

- **뜻 보상 시스템 (우선 검토)**: 코어에서는 뜻 선택에 보상이 없어 모두 가장 약한 뜻으로 수렴할 위험이 있다. 뜻별 난이도 계수(예: 클리어 시간 × 0.8~1.0)나 결과 화면 보너스 표시로 강한 뜻을 고를 이유를 만든다. 계수 표는 코어 뜻 목록(`100_game_design.md` 4.1)이 확정된 뒤 작성
- 다세트 라운드: 매치당 맵 교환 1회 → 2~3세트로 확장 (세트별 뜻 재선택)
- 패타임 돌파 보너스: 상대가 제작자의 검증 기록(패타임)을 넘기면 결과 화면에 강조 표시
- 맵 템플릿/추천 프리셋: 그리기 부담 완화용 기본 지형 제공
- 사운드 시스템: BGM/효과음 (에셋 목록은 `102_required_assets.md`)
