# SUMMARY — 프로젝트 요약

> **한 줄 컨셉**: 초지일관 — 스스로 걸은 제약("뜻")을 정하고, 그 뜻을 지킨 채 상대가 만든 맵을 클리어하면 이긴다.

## 기본 정보

| 항목 | 내용 |
|---|---|
| 장르 | 2D 플랫포머 + 드로잉 맵 제작 |
| 인원 | 2인 (3·4인은 확장 기획 — `101_extra_design.md`) |
| 엔진 | Unity 6 (6000.0.66f2 — 팀 전원 동일 버전), 2D URP, 신 Input System |
| 네트워크 | **Unity Multiplayer Services (Sessions + Relay) + Netcode for GameObjects** — 갈틱폰식 방 코드 참가. 외부 가입 없이 Unity 계정으로 완결 (`205_network.md`) |
| 개발 시간 | 약 15시간 (해커톤) |
| 팀 | 개발 4명 |

## 코어 루프

```
방 참가(방 코드)
   ↓
뜻 선언 (각자 자기 뜻 선택)
   ↓
맵 제작 (동시 진행, 드로잉 툴 — 시작점 고정, 골 배치)
   ↓
검증 플레이 (제작자가 "상대의 뜻"으로 자기 맵 클리어 → 패타임 기록)
   ↓
맵 교환 (각자 "자기 뜻"으로 상대 맵 플레이)
   ↓
기록 종합 → 랭킹 → 결과
```

- 플레이어 간 상호작용은 턴 기반 비동기 흐름. 플랫포머 플레이 자체는 각자 로컬에서 돌고 결과만 동기화 → 실시간 물리 동기화 불필요
- 검증은 상대의 뜻으로 해야 함 → 상대가 절대 못 깨는 맵 방지

## 경쟁 시스템 (요약)

- 점수 = `클리어 시간 × 뜻 계수 − 패타임(상대가 내 뜻으로 검증한 시간)`, 낮을수록 승 — "제작자보다 얼마나 빨랐나"로 비교하므로 질질 끄는 맵을 받아도 불리하지 않다. 클리어 > 미클리어, 둘 다 미클리어면 무승부
- 방 설정 5종 (호스트 값이 참가자에게 전달, 설정 UI 미구현 — 기본값 고정): 시도 제한 / 그리기 시간 제한 / **플레이 시간 제한**(검증·교환 플레이 공용 — 게임이 늘어지는 것 방지) / 뜻 개수 / 뜻 후보 수
- 상세: `206_ranking.md`, `100_game_design.md`

## MVP 범위

1. 방 생성/코드 참가, 방 설정 5종 (기본값 고정), 같은 방 라운드 반복
2. 뜻 목록 3~5종 (코드 강제 가능한 것만) — 목록에서 1개 선택, "뜻 없음" 불가
3. 드로잉 에디터: 펜(벽 선) + 골 배치 (+실행취소)
4. 검증 플레이 (상대 뜻으로 클리어 → 패타임 기록)
5. 맵 교환 → 플레이 → 기록 → 결과 화면
6. 2인 전용

## 폴백 전략 (시간 부족 시)

| 대상 | 폴백 |
|---|---|
| 드로잉 맵 | 스트로크 → `EdgeCollider2D` 선 물리로 단순화 (면 채우기는 처음부터 스코프 아웃) |
| 방 설정 UI | 기본값 코드 고정 — UI 없이도 게임 성립 |
| 결과 화면 | 텍스트 기반 최소 구성 |
| 3·4인 | 구현 안 함 (2인 고정) |
| 아트 | 기본 스프라이트 + 단색 — 아트 스타일은 후배치 가정 (`201_common.md`) |

## 기술적 핵심 결정

- 스트로크는 **이미지가 아닌 벡터 데이터(점 목록)**로 저장 → 콜라이더 변환 + 아트 스타일 재렌더링 모두 가능
- 네트워크는 NGO의 이름 붙은 메시지만 사용 (NetworkVariable·NetworkTransform 등 실시간 동기화 기능 미사용). 맵 데이터는 4KB 청크로 분할 전송 → `205_network.md`
- 씬 5개 분할, 1인 1씬 소유, 애디티브 로딩으로 통합 → `201_common.md`
- 씬 간 데이터는 `DontDestroyOnLoad` 싱글턴(`MatchData`)으로 전달
- 조작: A/D·←/→ 이동, W/↑ 점프, **R 리스폰(시도 +1)**. 낙하는 자동 리스폰(시도 미소모) → `202_gameplay.md`
- 캔버스 경계: 바닥·왼쪽 벽 고정 콜라이더, 천장·오른쪽 개방. 골은 제작자가 직접 배치(필수, 자동 배치 없음) → `203_map_editor.md`
