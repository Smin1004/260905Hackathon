# 202 — 게임플레이 구현 (Play 씬)

> 플랫포머 물리와 뜻(제약) 시스템의 구현 설계. 소유: 게임플레이 담당.
> Play 씬은 검증 모드와 교환 플레이 모드가 같은 씬을 공용한다. 룰 근거: `100_game_design.md`.

## 1. 플레이어 컨트롤러 사양 (조작 구성 확정 2026-09-05)

조작: 이동 **A/D 또는 ←/→**, 점프 **W 또는 ↑** (누른 길이로 높이 조절), 빠른 낙하 **S 또는 ↓**. 스페이스바 없음. 벽점프·벽 미끄러짐·대시·홀드 연속 점프는 **넣지 않는다** (뜻 재료로 보류).

| 항목 | 확정값 | 비고 |
|---|---|---|
| 물리 | `Rigidbody2D`(Dynamic, Continuous, 회전 고정) + `BoxCollider2D` 0.6×0.9 | |
| 이동 속도 | 5 u/s | |
| 지상 가속 / 감속 | 0.05초 / 즉시 | 방향 전환도 즉시 제동 후 가속 |
| 공중 가속 | 0.1초 | 지상보다 살짝 둔함 |
| 최대 점프 | 점프 속도 10 → 높이 ≈ 2.5u | |
| 가변 점프 | 키를 떼면 상승 속도 ×0.5 → 최소 높이 ≈ 0.6u | |
| 상승 / 하강 중력 | 2.0 / 3.2 (gravityScale) | 비대칭 |
| 빠른 낙하 | S/↓ 홀드 시 하강 중력 ×1.6 | |
| 꼭짓점 체공 | 상승 속도 < 1.5 이고 점프 홀드 중 중력 ×0.5, 최대 0.1초 | |
| 낙하 속도 상한 | 20 u/s | 얇은 선 터널링 방지 |
| 코요테 / 점프 버퍼 | 0.1 / 0.1초 | |
| 모서리 보정 | 0.15u | 상승 중 머리가 걸리면 옆으로 |
| 턱 자동 오르기 | 0.15u | 거의 수직인 면(|n.x|≥0.8)만 |
| 지면 판정 | 발 아래 BoxCast 0.12u, 노멀 40~140° | 경사 ±50°까지 지면 |
| 경사 | 접선 방향 이동, 정지 시 마찰 1.0 재질 / 이동 시 0 | 미끄러짐·떨림 없음 |
| 리스폰 | 사망 위치에서 0.2초 정지 후 시작점 (타이머 계속) | `PlaySession.RespawnDelay` |
| 피드백 | 스쿼시 앤 스트레치, 착지 먼지, 절차 생성 효과음(점프·착지·사망) | 아트·오디오 에셋으로 교체 가능 |

- 시작 위치: `MapData.StartPos` (고정 좌표 — `203_map_editor.md`)
- 기본 경계: **바닥과 왼쪽 벽 콜라이더는 Play 씬의 고정 오브젝트** (맵 데이터와 무관). 천장·오른쪽은 개방 — 오른쪽 끝을 지나 걸어 나가면 바닥이 끊겨 낙하하므로 x 우측 한계도 낙하 판정에 포함
- 위 값은 전부 `PlayerController` 공개 필드 — **뜻(제약)은 이 값과 입력 훅(`MoveOverride`, `JumpHeldOverride`, `RequestJump`)을 바꾸는 모듈**로 구현한다 (2장)

## 2. 뜻(제약) 시스템 구현

### 설계 방식 (구현: `Scripts/Common/Vows.cs`)

컨트롤러는 기본 성능을 가지고, **뜻은 컨트롤러의 공개 파라미터를 바꾸는 카탈로그 항목**으로 적용한다. 입력 필터 체인은 두지 않는다 — 1장의 값들이 전부 공개 필드라 파라미터 변경만으로 8종이 표현된다.

```csharp
enum VowId { None, SlowMove, LowJump, HeavyGravity, JumpCooldown, JumpLimit, NoAirControl, BigBody, Slippery }  // int 전송 — 뒤에만 추가

class VowDef { VowId Id; string Name, Description; int Tier; Action<VowContext> Apply; Func<VowContext, string> Status; }
static class VowCatalog { List<VowDef> All; RandomCandidates(count); Apply(ids, player, session); HudLine(ids, player, session); }
```

- `VowContext`: `PlayerController` + `PlaySession` 접근. `Apply`는 **스폰 직후 1회** 호출되어 파라미터를 바꾸므로 리스폰해도 유지된다
- `Status`가 있는 뜻(점프 쿨다운·점프 5회)은 HUD 한 줄에 실시간 상태를 덧붙인다 (`204_ui.md` 2.3)
- 새 뜻 = `VowId` 추가 + `VowCatalog.All`에 항목 1개. 뜻 목록·수치는 `100_game_design.md` 4.1

### 뜻별 구현 방식

| 뜻 | 구현 (바꾸는 파라미터) |
|---|---|
| 저속 | `MoveSpeed` ×0.5 |
| 저점프 | `JumpSpeed` ×0.71 (높이 ∝ v² → ×0.5) |
| 고중력 | `RiseGravity`·`FallGravity` ×1.6 |
| 점프 쿨다운 | `JumpCooldownAfterLanding` = 1.0s — 착지 후 쿨다운 동안 점프 차단, 남은 시간 HUD 표시 |
| 점프 5회 | `MaxJumpsPerAttempt` = 5 — 시도당 카운터, **리스폰(자동·R키)마다 초기화**, 남은 횟수 HUD 표시 |
| 공중 제어 금지 | `AirControl` = false — 점프 순간 수평 속도가 착지까지 고정 |
| 큰 몸집 | `ApplyBodyScale(1.5)` — 콜라이더·스프라이트 1.5배 |
| 미끄러운 발 | `GroundAccelTime` 0.5 / `GroundDecelTime` 0.6 / `IdleFriction` 0.05 + 재질 갱신 |

- 적용 시점: **검증 모드 = 상대 뜻**(`MatchData.OpponentVows`), **교환 플레이 모드 = 자기 뜻**(`MatchData.MyVows`) — 아래 3장
- 카운터형 상태(점프 횟수·쿨다운)는 컨트롤러가 리스폰 시 초기화
- HUD에 현재 뜻 상시 표시 (`204_ui.md`)

## 3. Play 씬 모드 구성

Play 씬은 하나이며, 모드 파라미터로 두 가지로 동작:

| 모드 | 맵 | 적용 뜻 | 기록 | 종료 후 |
|---|---|---|---|---|
| **검증 모드** | 자기 맵 | **상대의 뜻** | 클리어 시간 → 패타임으로 저장 | 매치 데이터에 패타임 반납 → 제출/대기 |
| **교환 플레이 모드** | 상대 맵 | **자기 뜻** | 클리어 시간 + 시도 횟수 → `PlayerRecord` | 결과 반납 → Result 전환 요청 |

- 모드 설정은 `MatchData` + 씬 진입 인자로 주입 (Boot FSM이 결정 — `205_network.md`의 매치 흐름)
- 두 모드의 차이는 데이터 주입뿐, 씬 내부 로직은 동일

## 4. 맵 로딩 (에디터 담당 납품 컴포넌트 사용)

- 에디터 담당이 전달한 **맵 로더 컴포넌트**(프리팹+API)를 통해 `MapData` → 콜라이더/렌더러 생성 — 파이프라인 상세는 `203_map_editor.md`
- Play 씬은 로더의 인터페이스만 호출: `ILoadableMap.Load(MapData)` — 구현 세부에 의존하지 않음
- 골 존: 골 위치에 트리거 콜라이더 배치, 플레이어 접촉 시 클리어 판정

## 5. 판정 & 진행 처리

| 처리 | 구현 |
|---|---|
| 골 판정 | 골 트리거 접촉 → 클리어, 타이머 정지, 결과 기록 |
| 경계 밖 낙하 | y 하한 또는 x 우측 한계 이탈 → **자동 리스폰**. 시도 미소모, **타이머 계속** (자연 패널티 — `100_game_design.md` 7.3) |
| R키 수동 리스폰 | 시작점 리스폰, `AttemptsUsed` +1, 뜻 상태 초기화, 타이머 계속. 갇힘 탈출용 — 검증·교환 모두 적용 |
| 시도 제한 | R키 리스폰으로 `AttemptLimit` 소진 시 미클리어 처리(GaveUp), 결과 전송 |
| 플레이 시간 제한 | 경과 시간이 `PlayTimeLimit` 도달 → 미클리어 처리(GaveUp). **검증 모드에서는 에디터 복귀** (`100_game_design.md` 6장) |
| 타이머 | 플레이 시작부터 골 도달까지 누적 (리스폰해도 리셋 안 됨). HUD에는 **남은 시간**(제한 − 경과) 표시 |
| 시간 동기화 | 시간 측정은 로컬, 기록 확정 시에만 네트워크 전송 (`205_network.md`) |

## 6. 카메라 (결정: 맵 전체 고정 시야)

- **맵 전체(30×15u)를 한 화면에 고정**으로 보여준다 — 추적 카메라 없음. 검증(에디터 안)과 교환 플레이(Play 씬) 모두 `CanvasView.FitCamera`로 맵 사각형에 맞춘다
- 근거: 캐릭터(0.6×0.9u)가 맵 폭의 1/50이라 전체 시야에서도 1920px 기준 약 38px로 충분히 식별된다. 제작자가 그린 맵을 한눈에 읽는 것이 드로잉 맵 게임의 핵심이고, 에디터 화면과 플레이 화면의 시야가 같아 검증 감각이 그대로 유지된다
- 후처리(톤 통일)는 선택 사항 — `201_common.md` 아트 방침

## 7. 테스트 체크리스트

- [ ] 각 뜻별로 실제 강제되는지 (8종 — `100_game_design.md` 4.1)
- [ ] 낙하 → 자동 리스폰 → 타이머 유지, 시도 미소모 확인
- [ ] R키 리스폰 → 시도 +1, 점프 카운터 초기화 확인
- [ ] 플레이 시간 만료 → 미클리어 처리(교환) / 에디터 복귀(검증) 확인
- [ ] 오른쪽 개방 경계로 걸어 나갔을 때 낙하 판정 → 자동 리스폰
- [ ] 맵 로딩: 스트로크 60개급 맵에서 프레임 저하 없는지
- [ ] 검증 모드/교환 모드 전환이 파라미터만으로 정상 동작하는지

## 8. 구현 현황 (2026-09-05)

| 파일 | 역할 |
|---|---|
| `Scripts/Play/PlayerController.cs` | 1장 확정 사양 전부 구현. 입력은 `Keyboard.current` 직접 읽기 |
| 손맛 보정 | **코요테 타임 0.1s** (지면을 떠난 직후 점프 허용 — 절벽 끝 점프), **점프 버퍼 0.1s** (착지 직전 입력을 착지 즉시 실행). 둘 다 `PlayerController` 공개 필드로 튜닝 |
| 경사 처리 | 이동 시 속도를 지면 접선 방향으로 주어 경사를 따라 붙어 이동(튐 없음). 정지 시 마찰 1.0 재질로 교체해 정적 마찰로 세우고, 이동 시 마찰 0 재질로 교체해 벽·경사에 붙지 않음 → 경사 미끄러짐·떨림 제거 |
| `Scripts/Play/PlaySession.cs` | 플레이 1회 세션(씬 무관): `MapLoader`로 맵 로드(콜라이더 포함) → 플레이어 스폰 → 타이머 → R 리스폰(시도 +1) → 경계 밖(y<-3, x<-3, x>33) 자동 리스폰(시도 미소모) → `GoalZone.Reached` 시 `Completed(PlayResult)`. ESC/버튼 → `Aborted`. HUD 런타임 생성 |
| 검증 모드 | MapEditor 씬 안에서 `MapEditorController.StartVerification()`이 PlaySession 을 띄운다 (3장의 "검증 모드"). 골 도달 시 클리어 시간이 패타임으로 `MatchData.MyParTime`에 기록되고 2.5초 후 에디터 복귀. 맵을 수정하면 검증 무효 → 재검증 |
| 교환 플레이 모드 | 미구현 — Play 씬을 만들고 `PlaySession.Begin(MatchData.OpponentMap, ...)` 으로 같은 세션을 쓰면 된다 |

미구현: 스프라이트 애니메이션. 카메라는 맵 전체 고정 시야로 확정 (6장 — 추적 카메라 없음).

> 주의: MapEditor 씬은 `Application.runInBackground = true`를 켠다. 에디터 창이 포커스를 잃으면 플레이 모드가 멈춰 타이머·물리가 진행되지 않기 때문 (멀티 대기 중에도 필수). Boot 씬이 생기면 그쪽으로 옮긴다.
